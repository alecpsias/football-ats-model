# Model-to-chat simulation execution contract

The NFL and CFB engines are **separate**. Their pregame results are not interchangeable.
An LLM narrative, a forecast from an older GitHub run, or a successful unit-test
workflow is **not** evidence that a newly requested game was simulated.

## Required intake for a fresh investigation

1. Check that the game is still pre-kickoff. Refuse a new pregame prediction for a
   completed or started game; use the separate postgame audit instead.
2. Submit an owner-authored GitHub issue through the connected GitHub interface.
   * NFL title: `NFL Matchup Request`
     Body: `{"kind":"nfl_matchup_request_v1","team_a":"NE","team_b":"CHI","game_id":null}`
     Use NFL schedule abbreviations (e.g. NE/CHI), not team nicknames.
   * CFB title: `CFB Matchup Request`
     Body: `{"kind":"cfb_matchup_request_v1","mode":"pregame","team_a":"New Mexico State","team_b":"Sam Houston","game_id":null}`
     Use exact full school names found on the current ESPN schedule.
3. Locate the workflow generated by **that** issue (not the latest unrelated scheduled run).
   If it fails, is skipped, or cannot identify the requested fixture, declare
   the simulation unavailable. Do not infer results from a prior forecast.
4. Read the archived original JSON and its `.proof.json` receipt from the
   successful action, checking:
   * `status=VERIFIED_5000_SIMULATIONS_RESEARCH_ONLY`
   * correct league, matchup, game ID, GitHub run/commit and snapshot provenance
   * exactly `primary_runs=5000` and `challenger_runs=5000`
   * creation before kickoff and a matching SHA-256 of the archived result
5. Only then describe the output as **5,000 simulations executed**. Use the
   unchanged baseline as primary; include the sole research challenger separately.
   Report the mean home margin, scenario tails and important statistical limitations.
   Independently research actual injuries and a timestamped, **signed** market line
   before a directional ATS evaluation; the model does not fabricate or infer odds.

## Where proofs live

* CFB owner issue: `cfb/archive/reviews/<GITHUB_RUN_ID>.json` and
  `cfb/archive/reviews/<GITHUB_RUN_ID>.proof.json`.
* NFL owner issue: `nfl/archive/requests/<GITHUB_RUN_ID>.json` and
  `nfl/archive/requests/<GITHUB_RUN_ID>.proof.json`.
* NFL scheduled runs (separate from requests): per-game receipts in
  `run-metadata/receipts/` inside the associated **ephemeral** GitHub artifact.
* CFB scheduled frozen forecasts: 5,000-run simulation fields live in their
  immutable frozen records. They are not substitute proofs for a newer requested run.

The receipt verifier (`simulation_receipt.py`) fails closed if an executed
baseline/challenger is absent, has a different run count, lacks required
provenance, or was computed too late. If statistics are missing and the
pipeline returns a pass/blocked status, no receipt is published.

The CFB historical backtest is a separate retrospective research workflow
with its own replay count. It is not used as a fresh requested prediction.

The project uses permitted free data only. All simulation probabilities
remain **uncalibrated research estimates**; a verified run does not imply a
profitable, certain, or validated ATS selection.
